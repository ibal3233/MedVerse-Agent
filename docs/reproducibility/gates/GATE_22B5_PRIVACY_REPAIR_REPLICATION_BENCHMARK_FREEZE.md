# Gate 22B.5 — Privacy Adaptive-Repair Replication Benchmark Freeze

## Why the claim boundary changes
Gate 22B.2 exposed the complete 162-state core formed by jurisdiction, disclosure authorization, minimum necessary, purpose declared, and audit required. Therefore no later benchmark using the same variable domains can honestly be called an unseen semantic-core benchmark.

## Scientific role
Gate 22B.5 is a fresh exact-record/context replication benchmark for the adaptive repair that follows Gate 22B.4. It uses the same 162 policy cores under three new request contexts: clinical data quality review, institutional access recertification, and privacy impact reassessment. Total = 486 records.

## Protected diagnosed cores
The seven policy cores that failed Gate 22B.3 are explicitly tagged so that their post-repair performance can be reported separately.

## Claim boundary
A future PASS supports repaired competence over the already-defined finite synthetic Privacy state space under fresh contexts. It does not demonstrate generalization to unseen Privacy semantics. A genuinely new semantic benchmark would require additional policy-grounded state variables/domains and a new oracle-grounding exercise.

## Next gate
Gate 22B.6 may add balanced oracle-consistent support for the three diagnosed precedence families, keep the oracle and logistic-regression family unchanged, reselect C using DEV only, preserve hyperparameter-table and training-history reporting, and evaluate once on this frozen replication benchmark.
