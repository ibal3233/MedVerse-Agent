# Gate 30 - Integrated Demonstration and Submission Release

Version 1.0. Additive integration on the immutable cumulative Gate 29 package.
The target is deployable local demonstration fidelity, NOT another algorithm-superiority claim.

## Thirteen required reporting elements
1. **Question.** Does the actual HTTP/UI execution path preserve the frozen selector's snapshot decisions and safely apply institution-owned proposals to progressively released scenarios, including revalidation before commitment?
2. **Frozen assumptions.** Trusted local modeled event publisher and authority register; no real patient data, hospital credentials, signatures, legal approval or external actions. All 18 source families are already known from Gate 29. Six release phases are event indices, not clinical time thresholds. The original two-event freshness parameter is inherited. Source interpretations remain pending independent clinical/Korean legal review.
3. **Changed component.** An additive integration adapter, persistent commit ledger, HTTP service and new UI. The original Gate 29 selectors, validator, reference evaluator, inputs and all older gates remain unchanged. All methods use the same adapter. No training, retrieval tuning or baseline weakening.
4. **Dataset and provenance.** Eighteen frozen institution-owned scenario models, four previous development and fourteen previous confirmation families. Known-data HTTP snapshot replay: 18 x 4 methods. Progressive replay: 18 x 4 x six event steps. These are regression records, not new independent cases. Default cross-track demonstration is C12. Phase 1: Hospital observation only; 2: clinical/cyber contracts; 3: original research contracts; 4: original DT/oversight contracts; 5: alternative contracts and non-research authority; 6: remaining alternative research authority. Original DENIED/PENDING records are never promoted.
5. **Split.** No new generalization split is claimed. Development instrumentation uses only D01, D04, D05, D06 plus explicit protocol probes. Former confirmation cases are known-data integration regression. Per-family summaries report the fourteen-family subset for comparability, not fresh confirmation.
6. **Leakage audit.** Runtime receives only released contracts and records. Source family labels, track, split, private role observations, future authority records and reference outcomes are removed from selector inputs. Private observations are returned only in role projections within a trusted local operator console. This is not cryptographic peer isolation. Unreleased contract mutation must leave the current prefix unchanged. No reference evaluator is imported by the runtime engine.
7. **Reference evaluation.** Unchanged independently coded (same developer) Gate 29 reference evaluator is run offline by the harness, never in the service. Snapshot objectives/dispositions/committed constraints are compared. Progressive selection is assessed on the residual task after fixed prior commitments. Cumulative prior effects are preserved, including joint-disclosure constraints. Incremental disclosure costs concern newly selected actions; no globally optimal foresight claim. Every newly committed action is assessed against its released state. Plan/commit probes record action identity and no side effect on rejection.
8. **Metrics.** Snapshot objective/disposition agreement, complete feasible workflows (report only nonzero denominators), per-event progressive objective/disposition agreement, invalid newly committed actions, duplicate effects, receipt integrity, role projection errors, temporal rejection probes, HTTP p50/p95/p99 with repeated trials and excluded warmups. Browser checks are a separate layer; failure is retained. No aggregation of test counts into an accuracy across unrelated denominators.
9. **Pass/fail.** Engineering integrity requires frozen-file verification, all declared engineering boundary checks, zero independently detected invalid new commits, no duplicate effects, intact receipt chains and snapshot parity for the capable methods. Comparative superiority is separate and not required. A valid scope-control miss is not an engineering failure. Any progressive reference disagreement is retained and diagnosed; no re-labeling after measurement. Browser evidence and independent review have separate statuses. No claim of perfection or production readiness.
10. **Raw outputs.** Unique timestamped run: HTTP response traces, selected proposals, actual commit receipts, state hashes, offline reference summaries, case/event CSV and JSON, temporal probes, per-request latency records, check results, source inventory, environment and protocol hashes. Exports are inspectable in the live interface. Figures point to their exact run and input hashes.
11. **Interpretation.** A successful integration shows that the demo uses the tested module and enforces modeled boundaries. It cannot establish universal superiority, lawful clinical practice, correctness of policy interpretation, or a genuine cross-platform standards gap. Capable ties are preserved. Any timing advantage is descriptive and includes loopback HTTP, not network/LLM/human latency.
12. **Claim boundary.** Deterministic, finite, internally authored institutional workflow models. Real-source-derived candidate KB; no new legal-source validation. BM25 is the live retrieval backend. No live LLM or saved classifier generates Gate 30 proposals. Two local DT adapters are not full ITU conformance. Review pending.
13. **Next dependency.** Native Windows/Spyder replay, qualified review of the exact clinical and policy contracts, independent scenario authorship, then final report/video/repository submission review. Do not reopen Gates 26-29.

## Presentation plan (fixed before measurement)
- Case-by-method glyph outcome matrix: complete, appropriate partial, or missed available obligations. Show capable ties.
- Progressive event/obligation raster for the C12 live run: events versus actual achieved obligations; not a narrative reconstruction.
- Empirical latency distribution (ECDF) for repeated actual HTTP calls, with exact measurement scope.
- One compact table separating historical architectural scores, current integration fidelity, and unresolved evidence.
No bar charts or opaque weighted composite are needed. PDF/PNG export and display run from the main gate entry point.

## Timing protocol
One excluded warmup replay per configuration; ten measured repetitions of six released events for C12 in randomized balanced order using seed 3001. Report 60 event-call observations per configuration. Timing is neither a gate threshold nor a tuning target.

## Versioning
The original launcher remains untouched. `run_integrated_sandbox.py` starts this release; `run_final_sandbox.py` continues to run v1. Original archived hashes are verified. The scientific files are frozen before integration evaluation. Presentation files are tracked separately and can be amended without changing measurements.
