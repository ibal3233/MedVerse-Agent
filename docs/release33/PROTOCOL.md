# Gate 33 — Commitment workspace integration and per-institution evidence

Version 1.0.0. This is an integration regression using known Gate 32 cases, not a new scientific confirmation or a repair of those cases. All original files and methods are preserved.

## Required experimental elements

1. **Question.** Does a progressive HTTP/operator interface reproduce the frozen commitment engine's decisions, actual effects, and receipts while clearly exposing timing conditions and per-agent contribution?
2. **Frozen assumptions.** Trusted modeled event publisher; original timing, authority, action, source, and event definitions; same selector and runtime validator. Model event limits are not clinical deadlines. Clinical/legal interpretation review is pending. No remote credentials, actual care, or real disclosures.
3. **Changed component.** Only integration and presentation: token-scoped local HTTP sessions, one-event release adapter, role projections, timing-contract display and receipt export. The original clinical/DT application remains on `/foundation`, with its original coordination logic. A common host is not a common patient state.
4. **Dataset and provenance.** All 12 existing prefix families: 4 development families/8 continuations and 8 historical confirmation families/32 continuations. Three controllers. Frozen institution-owned proposal contracts, not a newly trained model or live LLM. Total 120 replays and 720 modeled events. The word confirmation refers to Gate 32 history only.
5. **Split.** No new selection or tuning is performed. Preserve the original split fields for reporting and use all cases as integration regressions. Web-wrapper development uses P01 and P07 explicitly; subsequent replays remain known-input tests.
6. **Leakage audit.** The server's trusted fixture feeder holds the scenario but supplies one released event to the unchanged Session. The HTTP catalog discloses operator labels, not future event payloads or reference outcomes. The controller receives neither family/branch labels nor the timeline. Identical-prefix checks compare original engine state, excluding operator-only metadata. Export includes released input only. Role inspection is an operator tool, not proof of real authenticated peer isolation.
7. **Reference evaluation.** Compare every HTTP-produced engine-state hash and exported raw trace to a direct execution of the same frozen engine. This verifies faithful integration, not independent algorithmic correctness. Separately retain the original reference evaluator for end-of-run metrics. Archived primary results and all prior gate results remain unchanged.
8. **Metrics.** Exact per-event engine-state agreement; full-trace agreement; receipt integrity; invalid new commits under the existing reference checks; completion/clinical-timeliness/wait counts as historical regression measures; per-role decision opportunities, waits, preparations and commits; unauthorized endpoint/input rejection; actual loopback HTTP timing (descriptive only). No independent-patient or agent-learning accuracy claim.
9. **Pass/fail.** Integrity requires all wrapper checks, every event and trace match, valid receipt chains, zero observed invalid commits, matching known summaries, and unchanged predecessor files. It does NOT require 100% workflow completion, improvement over capable controls, dense execution or clinical approval. Report browser status separately and honestly.
10. **Raw outputs.** Source/freeze manifests, HTTP event comparisons, raw exports, case metrics, strategy and per-role summaries, same-history and authority-change tests, environment and frontend checks. Timestamped output directories. Every runner saves PNG/PDF/table and displays figures by default.
11. **Interpretation.** Successful integration makes the experimentally tested timing profile inspectable. Four gains/three losses and the fair-control tie are preserved. New UI metadata cannot repair old C01/C02 or retroactively validate timing contracts. A COMMIT proposal is not a committed effect. Preparation is not clinical completion.
12. **Claim boundary.** Local modeled workbench; same-developer specification; historical cases; no external clinical/legal validation, remote trust, cryptographic identity, ITU certification or universal multilingual performance. Exact Korean evidence remains real-source-derived candidates. Dense is selectable with no automatic fallback; its execution status is reported separately.
13. **Next dependency.** Local Windows/browser replay and qualified review of active timing/source interpretations, then final report and video from the selected immutable release. Do not make waiting the default in the original clinical workflow without an appropriate reviewed contract and separate evaluation.

## Locked scope

No changes to Gate32's controller, selector, action set, review windows, deadlines, penalties or outcomes. Do not retune these known continuations. Any UI bug fix is logged separately from scientific changes. No automatic refreeze is provided.

## Presentation

Prefer a per-institution evidence matrix, an actual decision-to-effect timeline and a compact method table. Always mark counts as opportunities or effects; do not call them per-agent predictive accuracy. The original clinical workspace and new commitment workspace are separate modeled sessions on the same local service.
